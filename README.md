# STM32 1A2B 猜數字遊戲（midtext2）

> NUCLEO-G474RE 期中專題｜STM32CubeIDE + Python UART GUI
>
> 專題狀態：程式已整理；實際編譯、燒錄與硬體測試結果請依完成情況補充。

## 1. 情境故事

希望把常見的「1A2B 猜數字」做成可以動手玩的嵌入式小遊戲。玩家在電腦上的 Python 視窗輸入四位數字，STM32 負責判斷結果，麵包板上的四顆 LED 會同步顯示每個位置的判定。按下實體按鈕就可以公布上一局答案、重新開始。

## 2. 替身對應（故事 → 板上替身）

| 遊戲中的角色 | 板上／電腦的對應元件 | 用途 |
| --- | --- | --- |
| 出題者 | STM32G474RE 微控制器 | 產生答案、判斷 A/B |
| 玩家輸入區 | Python UART 圖形介面 | 輸入四位數字、送出猜測 |
| 判定提示 | 四顆 LED | 依輸入位置顯示 A、B 或錯誤 |
| 重新開始 | PA0 外接按鈕 | 觸發新遊戲 |
| 遊戲紀錄 | UART 通訊視窗 | 顯示猜測次數、答案與新局通知 |

## 3. 功能與驗收條件

- STM32 產生四位**互不重複**的數字；答案可以以 `0` 開頭。
- 第一位玩家操作的時間用於初始化偽隨機種子；新局答案不能與前一局相同。
- 玩家輸入四位不重複數字並按 Enter 後才進行判定。
- `A`：數字正確且位置正確；`B`：數字正確但位置錯誤。
- 四顆 LED 分別代表輸入的第 1～4 位：`A` 常亮、`B` 呼吸、錯誤熄滅。
- 呼吸燈約 **1 秒漸亮、1 秒漸暗**。
- PA0 按鈕使用下降沿外部中斷，並設有 **200 ms** 防重複觸發。
- 按鈕中斷只提出重開要求；主迴圈公布舊答案、產生新答案、清除 LED 和猜測次數。
- UART 訊息格式與 Python 介面相容，例如：

```text
Round 1: 1478 -> 1A1B
Answer: 1234
New game!
```

> 上面是**通訊格式示例**，不代表已取得這組實測結果。

## 5. 腳位表

**開發板：** NUCLEO-G474RE，系統時脈 170 MHz。

| 腳位 | 功能 | 設定與用途 |
| --- | --- | --- |
| PA2 | LPUART1_TX | 傳送 UART 訊息給電腦 |
| PA3 | LPUART1_RX | 接收電腦輸入 |
| PA6 | TIM3_CH1 | 第 1 顆 LED（第 1 位） |
| PA7 | TIM3_CH2 | 第 2 顆 LED（第 2 位） |
| PB0 | TIM3_CH3 | 第 3 顆 LED（第 3 位） |
| PB1 | TIM3_CH4 | 第 4 顆 LED（第 4 位） |
| PA0 | EXTI0 | 外接按鈕；內部上拉、下降沿觸發 |

**UART：** 115200 bps、8N1，程式以輪詢接收。

**TIM3：** Prescaler = `169`、Period = `999`、PWM mode 1、High polarity。

**接線提醒：** LED 需要適當的限流電阻；按鈕配合內部上拉，按下時將 PA0 接至 GND。實際接線請依開發板與麵包板配置確認。

## 6. 建置與執行

### STM32 端

1. 使用 STM32CubeIDE 開啟 `midtext2` 專案（`.ioc` 與 `Core/`、`Drivers/` 等專案檔）。
2. 確認 `Core/Src/main.c` 是本專題版本，並檢查 EXTI0 中斷函式與 GPIO 定義。
3. 執行 **Build**，確認無編譯錯誤。
4. 使用 ST-LINK 下載韌體至 NUCLEO-G474RE。
5. 將四顆 LED 與 PA0 按鈕接好。

### Python 端

1. 在 PyCharm 建立 Python 專案，加入 `UART_GUI_midtext2.py`。
2. 於終端機安裝 UART 套件：

```bash
python -m pip install pyserial
```

3. 使用 USB 連接開發板，確認 Windows 裝置管理員中的 COM 埠。
4. 執行 Python 程式，選擇 COM 埠並按「連線」。
5. 輸入四位互不重複的數字（例如 `0123`），按「送出猜測」。
6. 觀察視窗中的 `Round ... -> xAyB` 及四顆 LED 的變化。
7. 按 PA0 外接按鈕，確認出現 `Answer: ...` 和 `New game!`。

## 7. 程式結構

```text
midtext2/
├── Core/
│   ├── Inc/
│   │   └── main.h                 # GPIO 與共用定義
│   └── Src/
│       ├── main.c                 # 遊戲、UART 輪詢、PWM 控制
│       ├── stm32g4xx_it.c        # 中斷服務函式
│       └── stm32g4xx_hal_msp.c   # 周邊底層初始化
├── Drivers/                       # STM32 HAL 驅動
├── midtext2.ioc                   # CubeMX 設定檔
└── ...                            # 其他 IDE 專案檔

Python/
└── UART_GUI_midtext2.py          # 電腦端 UART 圖形介面

docs/
└── ...                            # 硬體照片與測試截圖
```

**主迴圈與中斷分工：** EXTI0 中斷只記錄有效按鈕事件、設定重開旗標；主迴圈負責處理重開事件、UART 接收、猜測判定與 LED 呼吸更新。避免在中斷中執行較長的 UART 輸出和遊戲重設工作。

## 10. 已知限制與後續改善

- UART 接收採用短逾時輪詢，傳送訊息時仍可能短暫阻塞主迴圈；可改為中斷或 DMA 優化。
- 偽隨機答案不是硬體真亂數，適用於課堂遊戲，不適合保密或安全用途。
- 按鈕防彈跳是軟體時間判斷，接線與機械開關狀況仍會影響實際效果。
- Python GUI 需要正確的 COM 埠及 `pyserial`；同一 COM 埠不能同時被多個程式占用。
- 最終編譯、燒錄及測試狀態以本專案實際執行紀錄為準。
